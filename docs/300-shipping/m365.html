Level 300 / Shipping

M365 Copilot and SharePoint

The lowest barrier to entry in the whole stack. You describe the workflow in a chat and Copilot writes the file for you.

Authoring by conversation

In Copilot in SharePoint you don't open a text editor. You describe the workflow and confirm the draft.

  1. Open the Copilot chat panel on the site.
  2. Describe the repeatable workflow you want.
  3. Copilot returns a draft skill definition.
  4. Ask for adjustments.
  5. Confirm to save.

A real one from the shop:

Create a skill to check incoming consignment paperwork. Verify each form has an artist name, a contact email, a title count, and an agreed split in the format 60/40. If any field is missing, add the form's file name to the Incomplete Consignments list.

That's the whole authoring step. Marcus did this from his phone.

Where it ends up

Agent Assets/
  Skills/
    consignment-paperwork-check/
      SKILL.md

The Agent Assets library is created and managed by the product, and can't be deleted. The skill is a plain markdown file in there, and you can open and edit it directly if you'd rather work in the file than in the chat. Keep the format intact when you do.

Why this matters more than it sounds

The file is a normal SharePoint document. That means versioning, retention, sensitivity labels, and audit already apply to it, with no new governance surface to configure. Your skills inherit the governance your documents already have.

Permissions

Action Requires
Create or edit a skill Edit permission on the site
Use a skill View permission on the site
Restrict further Break inheritance on the Agent Assets library

There are no separate admin controls to switch skills on or off. Standard SharePoint governance is the control surface.

What SharePoint skills can and can't do

Can

Understand and summarize content. Organize files and folders. Read and write SharePoint lists. Chain built-in Copilot capabilities into multi-step sequences.

Can't

Connect to external systems. Execute custom code. Do anything the running user isn't already permitted to do.

That last one is the important one and it's the number one cause of "works for me, broken for them."

Test as a normal user

A skill runs with the permissions of whoever's using it, not whoever wrote it. If you're a site owner, your test proves almost nothing about what a member will experience. Borrow somebody's account or use a test member account, every time.

When SharePoint is the right shelf

Good fit

The work is already in SharePoint. Documents, lists, libraries. The people who need it are already on the site. Nobody involved wants to touch a repo.

Wrong fit

You need an external API, custom code, or a skill that follows a person across sites. That's Copilot Studio or a repo skill.
